## 1. Обзор проекта

Проект **Upgrade** — это специализированный интернет-магазин игровых компьютеров, готовых сборок, мониторов, ноутбуков и аксессуаров в Ташкенте (Узбекистан).

Исходный статический сайт состоял из разрозненных HTML-файлов со статическими карточками, неработающими формами авторизации и корзины, заглушкой вместо конфигуратора ПК и сторонним ботом.  
В версии **Upgrade 2.0** сайт полностью трансформирован в высокопроизводительное full-stack веб-приложение на базе **Next.js 14 App Router**, в котором каждая кнопка, форма, фильтр и процесс покупки работают на реальных данных и базе данных.

## 3. Стек технологий

- **Фреймворк**: Next.js 14 (App Router, Server Components + Client Components)
- **Язык**: TypeScript 5 (строгая типизация)
- **Стилизация**: Tailwind CSS v4 (`@tailwindcss/postcss`) + чистый CSS
- **База данных**: Prisma ORM (по умолчанию настроена локальная SQLite `prisma/dev.db` с нулевой зависимостью от внешних сервисов; легко переключается на PostgreSQL)
- **Безопасность и авторизация**:
  - `bcryptjs` для криптографического хеширования паролей (12 раундов)
  - `jose` для создания и валидации защищенных JWT-токенов
  - HTTP-Only Cookies (`upgrade_session_token`)
- **Валидация данных**: Zod (проверка email, телефонов, полей заказа и товаров)
- **Управление состоянием**: Zustand (с сохранением состояния корзины и избранного в `localStorage`)
- **Иконки**: Lucide React

## 4. Что было исправлено и улучшено

### 🔐 1. Авторизация и безопасность (Sign In / Sign Up)
- **Было**: Статическая нерабочая форма в модальном окне без обработчиков отправки и сохранения данных.
- **Стало**:
  - Полноценная регистрация по email и паролю с валидацией Zod.
  - Вход с генерацией защищенной сессии JWT (HTTP-Only Cookie).
  - Восстановление пароля (`/api/auth/forgot-password`).
  - Личный кабинет пользователя (`/profile`) с отображением имени, телефона, адреса и роли.
  - Возможность редактирования личных данных через API (`PUT /api/auth/me`).
  - Разделение прав доступа: обычный пользователь (`USER`) и администратор (`ADMIN`).
  - Защита административных разделов: доступ к `/admin` и API `/api/admin/*` строго ограничен (неавторизованные или обычные пользователи получают 403 Forbidden).

### 🛒 2. Корзина и товары
- **Было**: Статический бейдж с числом товаров, отсутствие сохранения при перезагрузке, кнопки не добавляли товары.
- **Стало**:
  - Интерактивное добавление любого товара в корзину с мгновенным открытием выпадающего меню.
  - Изменение количества (+ / -) и удаление позиций.
  - Автоматический пересчет итоговой суммы в узбекских сумах (UZS).
  - Живой индикатор количества в шапке (Header).
  - Сохранение корзины и списка избранного при обновлении страницы (`zustand/persist`).

### 📦 3. Оформление заказа (Checkout / Buy Now)
- **Было**: Статическая верстка страницы `pages/buynow.html` без сохранения заказов.
- **Стало**:
  - Страница `/buynow` с автозаполнением данных авторизованного пользователя.
  - Выбор способа доставки: «Стандартная курьерская», «Срочная доставка (Express)», «Самовывоз из шоурума».
  - Выбор способа оплаты: «Оплата при получении (Cash on Delivery)», оплата через терминал или согласование с менеджером.
  - При оформлении заказу присваивается уникальный номер (например, `UPG-2026-7842`).
  - Заказ сохраняется в базе данных Prisma и связывается с учетной записью клиента.
  - История заказов доступна в Личном кабинете (`/profile`) со статусами в реальном времени (`В ожидании`, `В обработке`, `Отправлен`, `Выполнен`, `Отменен`).

### 🛠️ 4. Конфигуратор ПК (PC Builder)
- **Было**: На странице `pages/configurator.html` отображалась статическая заглушка *"Страница в разработке"*.
- **Стало**:
  - Полноценный интерактивный конфигуратор ПК на странице `/configurator`.
  - Выбор 7 ключевых категорий комплектующих: Процессор (CPU), Материнская плата, Оперативная память (RAM), Видеокарта (GPU), Накопитель (SSD), Блок питания (PSU), Корпус.
  - **Движок проверки совместимости**:
    - Проверка сокетов (например, Intel LGA1700 vs AMD AM5).
    - Проверка поколений памяти (DDR4 vs DDR5).
    - Расчет энергопотребления сборки (TDP) и рекомендация мощности блока питания.
  - Динамический пересчет итоговой стоимости сборки.
  - Кнопка **«Добавить сборку в корзину»** — формирует единый комплект и добавляет его для заказа в один клик.

### 🔍 5. Каталог, поиск и фильтрация
- Каталог игровых сборок (`/igrovye-sborki`):
  - Полнотекстовый поиск по названию и бренду.
  - Фильтрация по брендам (ASUS, MSI, HyperX, 2E Gaming, Gigabyte, DeepCool и др.).
  - Сортировка: «Сначала дешевле», «Сначала дороже», «По названию».
  - Фильтрация по категориям (Компьютеры, Мониторы, Ноутбуки, Комплектующие).
- Страницы конкретных товаров (`/products/[id]`, `/pages-for-pace/asus1`, `asus2`, `asus3`, `monitor`) с галереей миниатюр, таблицей подробных характеристик и отзывами.
- Каталог брендов (`/trademarks`) с алфавитным указателем (A–Z).
- Страница новинок (`/news`).
- Страница «О компании» (`/information`) с фото команды и шоурума.

### 👑 6. Панель управления администратора (Admin Dashboard)
- Доступна по адресу `/admin` только для пользователей с ролью `ADMIN`.
- **KPI-метрики**: общая выручка, количество заказов, количество товаров на складе, количество активных заказов.
- **Управление заказами**:
  - Поиск по номеру заказа или контактам клиента.
  - Фильтр по статусам.
  - Моментальное изменение статуса заказа (`PENDING` → `PROCESSING` → `SHIPPED` → `COMPLETED` → `CANCELLED`).
  - Просмотр подробного состава любого заказа.
- **Управление товарами**:
  - Добавление новых товаров через модальную форму.
  - Редактирование цен, скидок, описания, остатков на складе и категорий.
  - Удаление товаров из каталога.

## 5. Авторизация и создание администратора

Система авторизации построена на безопасном хешировании паролей (bcryptjs) и JWT-сессиях:

- **Регистрация пользователя**: любой покупатель может зарегистрироваться через модальное окно «Sign Up» (имя, email, телефон, пароль).
- **Вход**: через модальное окно «Login».
- **Назначение роли Администратора (ADMIN)**:
  1. Зарегистрируйте аккаунт через форму на сайте (или передайте `ADMIN_EMAIL` и `ADMIN_PASSWORD` в переменные окружения перед запуском сидинга).
  2. В базе данных PostgreSQL установите поле `role = 'ADMIN'` в таблице `User` для нужного email.
  3. После этого пользователю станет доступна защищенная панель `/admin`.

## 6. Быстрый старт и запуск

### Системные требования
- **Node.js**: версия 18.18+ или 20+ (протестировано на Node.js v24)
- **npm** (или pnpm / yarn)

### 1. Установка зависимостей
В корневой папке проекта выполните:
```bash
npm install
```

### 2. Инициализация базы данных и сидирование
```bash
# Синхронизация структуры БД с Prisma
npx prisma db push

# Заполнение базы тестовыми товарами, комплектующими и аккаунтами
npm run seed
```

### 3. Запуск в режиме разработки (Dev Server)
```bash
npm run dev
```
Откройте браузер по адресу: **`http://localhost:3000`**

### 4. Продакшн-сборка и запуск
```bash
npm run build
npm run start
```

### 5. Запуск автоматических сквозных тестов
В проекте подготовлен скрипт сквозного E2E-тестирования всех маршрутов, авторизации и защиты прав:
```bash
npm run test:e2e
```

## 8. Erbol AI — Технический помощник

В исходном проекте в коде присутствовал идентификатор чужого агента Jotform (`019dbee292b87326b2c39b534f61097f15ac`), который приводил к показу бота друга.

### Что было сделано:
1. Чужой идентификатор бота полностью удален со всех страниц сайта.
2. Создан выделенный компонент `components/ErbolAI.tsx` с правильным позиционированием в правом нижнем углу экрана.
3. Отображаемое имя: **Erbol AI**  
   Подпись: **Тех. помощник**  
   Аватар: современная иконка технического ассистента в фирменных цветах Upgrade.
4. Виджет оснащен встроенным приветственным интерфейсом и готов мгновенно подключить ваш новый Jotform AI Agent.

### Как подключить ваш новый Jotform Agent:
Как только вы создадите своего агента в личном кабинете Jotform, откройте файл `.env` в корне проекта и вставьте полученный ID агента:
```env
NEXT_PUBLIC_ERBOL_AI_AGENT_ID="ВАШ_НОВЫЙ_JOTFORM_AGENT_ID"
```
Компонент `ErbolAI.tsx` автоматически подхватит этот ID, динамически загрузит официальный скрипт `https://cdn.jotfor.ms/s/umd/latest/for-embedded-agent.js` один раз (без дублирования при навигации) и активирует вашего персонального помощника.

## 9. Инструкция по переключению на PostgreSQL

Для локальной разработки проект настроен на **SQLite** (`prisma/dev.db`), что позволяет запускать и тестировать проект на любой машине без предварительной установки серверов баз данных.

Для перехода на **PostgreSQL** в production-окружении выполните 3 простых шага:

### Шаг 1. Измените строку подключения в `.env`
```env
DATABASE_URL="postgresql://username:password@localhost:5432/upgrade_db?schema=public"
```

### Шаг 2. Обновите `provider` в `prisma/schema.prisma`
Замените:
```prisma
datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")
}
```
на:
```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

### Шаг 3. Примените миграцию и наполните базу
```bash
npx prisma db push
npm run seed
```
После этого приложение будет работать с сервером PostgreSQL без каких-либо изменений в коде.
